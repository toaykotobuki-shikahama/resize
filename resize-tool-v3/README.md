# 用途別画像リサイズ

GitHub Pagesでそのまま公開できる、ブラウザ完結型の画像リサイズツールです。

## リポジトリへ入れるファイル

- `index.html`
- `styles.css`
- `app.js`
- `jszip.min.js`

4ファイルをリポジトリ直下へ配置してください。

## GitHub Pagesの設定

1. GitHubの対象リポジトリを開く
2. `Settings` → `Pages`
3. `Build and deployment` の Sourceを `Deploy from a branch` にする
4. Branchを `main`、フォルダを `/(root)` にする
5. `Save`

## 主な機能

- Googleマップ：1200 × 1200
- X：正方形／横型
- LINE：1040 × 1040
- モニター・横：1920 × 1080
- モニター・縦：1080 × 1920
- A4／A3：縦・横、300dpi相当
- 任意サイズ
- 余白追加／中央トリミング／引き伸ばし
- PNG／JPG
- 透明余白／背景色指定
- 複数画像のZIP保存

画像処理は利用者のブラウザ内で行われ、画像を外部サーバーへ送信しません。

出力ファイル名はCMS登録向けにハイフンで区切ります。元画像名の空白・アンダースコアもハイフンへ変換し、ZIP名と同名ファイルの連番にもアンダースコアを使用しません（例：画像名-モニター縦-2.png）。

## Ver.3.0：帯追加モード

1. 用途を選び、画像を複数追加します。
2. 「画像の収め方」で「帯を追加」を選びます。
3. 初期状態では、グラデーション→ストライプ→ドット→幾何学の順に切り替わり、画像の外周から色を取得します。そのまま保存できます。
4. 全画像で同じ帯を使う場合は「共通」を選び、帯デザインを選びます。「自動選択」は画像ごとに余白面積・方向・彩度を見て判定します。
5. 「順番切替」「ランダム」ではチェックした候補を使います。帯デザインのセレクトは共通モード専用です。候補は画面の並び順で適用され、最後の候補の次は先頭へ戻ります。
6. 「手動カラー指定」で色を選ぶこともできます。グラデーション・模様の副色はその色から自動生成します。
7. 画像一覧の「この画像の帯」で個別指定できます。「一括設定を使用」に戻すと個別指定を解除できます。一括設定を変えても個別指定は優先されます。
8. 用途ごとの「仕上がりプレビュー」を確認し、画像の↓で個別保存、下のボタンで一括保存します。

### 帯の仕様

- 単色／グラデーション／画像ぼかし／ストライプ／ドット／幾何学の6種類です。
- 元画像を中央に全体表示し、縦横比を維持します。帯は表示領域の外側だけに描きます。
- 画像ぼかしは元画像の各外周12%を別キャンバスでぼかし、対応する余白へ描画します。元画像へぼかしをかけません。
- 色は縮小画像の外周約11%から、透明・白・黒・無彩色を避けて代表色を取得します。外周で取れない場合は全体、取れない場合は落ち着いた青灰色を使います。彩度を下げ、明るさを調整します。
- デザイン自動選択：余白12%未満は単色、55%超は画像ぼかし、それ以外で低彩度は幾何学、左右余白はグラデーション、上下余白はストライプです。
- 余白がない画像は帯を追加しません。「WEB用・軽量」は従来どおり高さ自動なので、帯追加モードでも帯は付きません。
- ランダム用の値は画像を読み込んだ時に一度決めます。プレビュー・個別保存・一括保存で同じ結果になります。画像を削除して再追加した場合やページ再読み込み後は再抽選します。
- 1画像から複数用途を出す場合、順番・ランダムは画像単位で同じ帯になります。デザイン自動選択は用途ごとの余白を判定するため、同じ画像でも用途で変わることがあります。
- 帯追加は「PNGの余白を透明にする」より優先します。元画像内の透明部分は従来の保存設定に従います。
- 文字帯はありません。帯処理は独立した `bands.js` にまとめてあります。
- 帯画像とプレビューはページ内でのみ扱い、画像・カラーを外部へ送信しません。

### 処理負荷と対応

プレビューは出力と同じ解像度・形式・JPG画質で生成し、縮小表示します。大きな印刷サイズ、多数の画像、多数の用途を選んだ場合は処理時間・メモリ使用量が増えます。プレビュー生成は順次処理し、変更後の古い結果は表示しません。保存中は設定操作を無効にし、プレビューと保存内容の不一致を防ぎます。端末のメモリによる上限は従来同様で、Canvas初期化・書き出しの失敗は画面へ通知します。
