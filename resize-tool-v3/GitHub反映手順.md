# 既存GitHubリポジトリへの反映

1. 既存リポジトリを開き、更新前のソースを「Code → Download ZIP」でバックアップしてください。
2. 納品ZIPを展開してください。名前に `(1)`、`(2)` 等が付いた添付ファイルではなく、ZIP内の正式名を使います。
3. 既存リポジトリで「Add file → Upload files」を開いてください。
4. `index.html`、`app.js`、`styles.css`、`bands.js`、`jszip.min.js` を既存 `index.html` と同じ階層へアップロードしてください。フォルダごとアップロードして階層を増やさないでください。
5. `README.md`、`検証結果.md`、`GitHub反映手順.md` も必要に応じてアップロードしてください。
6. 「Commit changes」で更新します。例：`Ver.3.0 デザイン帯とローテーションを追加`。
7. 新規リポジトリ作成やPages設定変更は不要です。既存のPages対象ブランチに更新します。別ブランチで作業した場合は、既存の運用手順に沿ってPages対象ブランチへマージしてください。
8. 「Actions」でPagesの公開処理完了を確認し、既存の公開URLを開いて、ブラウザを強制再読み込みしてください（Windows：Ctrl + Shift + R）。
9. 下記の公開環境チェックを行ってください。

## 公開後の確認

- 「帯を追加」を選ぶと設定が開く。
- 縦長・横長のPOPを追加し、横1920×1080・縦1080×1920で欠けがない。
- 複数画像で帯が順に切り替わる。個別指定が一括設定より優先される。
- ランダムを選び、プレビューと保存結果が同じ。
- 個別画像・ZIPを保存でき、出力名にアンダースコアがない。
- 従来の余白、透明PNG、引き伸ばし、トリミング微調整が使える。
- 画像を端末から選び、通信を切っても変換できる（ページ読込後）。

表示が古い場合は強制再読み込みを行います。「帯を追加」で動かない場合は `bands.js` の配置とファイル名を確認してください。問題があればバックアップの元ファイルを同じ階層へ戻してコミットすると復旧できます。復旧時に新しい `bands.js` が残っていても元のHTMLでは参照しません。
